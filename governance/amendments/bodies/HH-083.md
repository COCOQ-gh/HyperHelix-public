# HH-083 — Distill の振り分け(D3/D4)を記録の必須欄にし、ホスト文書へ置いた知見には S2 で引ける入口を必須にする

**Status:** Approved(2026-10-26 ユーザー承認 — 「HH-083 を承認する」の直接指示。裁可事項 1〜3 とも)
**ratified_by:** COCOQ-gh
**ratified_at:** 2026-10-26
**種別:** ループ定義変更(standard/full の D3/D4 証跡の必須化・finish の fail-closed 範囲の拡大)+ 運用規約(routing.yaml のホスト文書の宛先・light の Distill 後回しの追跡)

## 背景

あるホストプロジェクトで続けて行ったタスクの作業記録を読み、Distill に書かれた知見と学習ノートの台帳を突き合わせた。

- 最初のうちは、知見をどこへ送るか(ノート・アンチパターン・ホスト文書・再利用しない)の判断が記録に書かれていた。
  途中から Distill の記録が 1 行に縮み、その判断そのものが記録から消えた。
- `core/loop.yaml` の standard は `required_steps` に D3・D4 を含むが、`finish` / `verify` は
  hh-record のスキーマ・`note_adds` の実在・HH-053 の帰属・HH-043 の「手戻り」語の検査しかしないため、
  必須ステップの欠落が黙って通り続けた。
- その結果、Distill に書かれた再利用できる知見の多くがノートにならず、S2 で引けなかった。
  同じ種類の誤りが後のタスクで繰り返され、ユーザーの指摘や手作業の修正で直すことになった。
  再発したので D6 が必須だったのに、アンチパターンにもノートにもならなかった知見もあった。

候補として挙がっていた他の原因は、記録では主因でなかった:

- **D7「1 タスク 1 件まで」(HH-077)**: 知見が落ちたタスクの大半はノートを 1 件も追加しておらず、枠は使われていない。
  枠が知見を押し出した例は無い。
- **S2 のプロジェクト警告**: 取得自体はできていた。知見は**ノートが存在しなかった**ので引けなかった。
- **light の後回し**: light で省いた Distill を後で埋めた記録は無かった。主因ではないが、同じ「後で送る知見が送られない」構造。

もう 1 つの構造: 後半は知見をホスト側の文書(手順書・運用手引き)へ書いて
Distill を閉じていたが、ホスト文書は S2 の検索範囲外で、ノートからの入口も無かった。
既存のノート(教訓は「次に読まれる場所」へ置く、retrieval のあるレールから必ず 1 本指す)がフレームワーク資材について
述べたことが、ホスト文書でも起きている。`core/routing.yaml` の routing にはホスト文書の宛先が無い。

## 裁可事項(案)

1. **振り分け表を hh-record の必須欄にする**: standard / full の hh-record に `distill_routing`
   (D1・D2 の知見 1 件ごとに `finding` と `destination` = note id / AP id / process-backlog / ホスト文書のパス + 入口のノート id /
   `not-reusable: <理由>`)を置き、`finish` / `verify` は空なら fail-closed にする。
   宛先にノート id を書いたら、その id が台帳に実在すること(`note_adds` と同じ検査)。
   既存の D3/D4 の手順(routing の宛先)は変えず、その結果を機械で見える形にするだけ。
2. **ホスト文書へ置いた知見には S2 の入口を必須にする**: `core/routing.yaml` に
   「host-project procedure / principles document」の宛先を足し、ホスト文書に置いた再利用知見は
   そのプロジェクトのノート(playbook 推奨)からパスを指すことを条件にする。
   ノート追加は D7 の裁量枠 1 件に数える(HH-077 は変えない)。既存の playbook の本文更新で指せるならそれでよい。
3. **light の Distill 後回しを数える**: light の hh-record に `distill_deferred`(省いた D ステップ)を置き、
   未消化の件数を `finish` の出力に表示する。次の standard タスクで埋めるか、理由を書いて破棄する。
   fail-closed にはしない(light の軽さを保つ)。

## 却下した代替案

- **(a) D7 の枠を増やす** — 枠は使われておらず、知見が落ちた理由ではない。
- **(b) Distill の書き方の注意をチェックリストに 1 行足す** — 上記の既存ノートのとおり、
  配送の無い注意は読まれない。今回も distill.md D4 の手順は存在したのに飛ばされ続けた。機械の検査が要る。
- **(c) すべての D1 をノートにする** — 台帳の churn が増え(HH-016 の趣旨に反する)、一度きりの知見まで溜まる。
  「再利用しない」と理由を書いて閉じる選択肢を残すのが正しい切り口。
