### 要求定義(S1)

**何を作るか**: HH-036(phase_gate↔artifacts↔required_steps の不整合)を検知できなかった根因を特定し、機械検出器を追加する。

**なぜ作るか**: ユーザー指示(2026-06-22「なぜ検知できなかったか、検知できる仕組みを作る」)。

**成功条件**:
1. 根因が D2 に明文化。
2. validate に `PHASE_CONSISTENCY` 追加: (a) dangling evidence(gate evidence 名が実在 artifact か=error)、(b) coverage(各フェーズの非条件 artifact が次フェーズ gate に在るか=warn)。陽性/陰性テスト済(N-018)。
3. R1 スイープ + AP-003 に新検査を配線。
4. `node tools/hyperhelix.mjs validate` パス。

**スコープ外**: checklist 散文の「mandatory」と required_steps の照合(#5/#8 — 散文解析が要り機械化困難。R1 手動+敵対監査に留置)。

### 取得ノート(S2 — 根因)

validate(hyperhelix.mjs)は schema/counters/notes/anchors/amendments索引/active-scan/GATE_DEAD_CONFIG を検査するが、**loop.yaml の phases.artifacts ↔ phase_gate.evidence ↔ required_steps の内部整合を検査しない**。HH-036 の穴(plan gate に retrieved-materials 欠落・execute gate に change-list 欠落・evaluate gate に failure-case-log 欠落)はすべて「フェーズが生む artifact を次フェーズ gate が消費していない」= loop モデル内 declare↔消費。R1 宣言↔消費スイープ(TASK-014)は手動散文で、loop モデルそのものには未適用。→ **根因: loop モデルの自己整合を検査する機構が機械にも(loop に関しては)手動にも無かった**。phase_gate/artifacts/evidence は構造化済で機械検査可能。
