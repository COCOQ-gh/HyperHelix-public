### 調査メモ(S2 — 根因分析)

**validate が検査するもの**(hyperhelix.mjs:330-387): 必須ファイル存在 / entrypoint / schema_version / counters / note スキーマ / next_note_id>max / FRAMEWORK_REVIEW トリガ / task-list / active-scan(撤去語) / anchors / amendments 索引↔見出し。
**validate が検査しないもの**: **宣言↔消費の配線(AP-003)** — gates param が消費されるか / brief 欄が agent-roles 宣言と一致するか / 参照先(destination)が実在するか / ルールが要求する検査の実装有無。意味的整合・**omission** も非対象。
**R1/R2 は手動**で、かつ「phase step 一致 + 参照ファイル存在」止まりで、**宣言↔消費を体系的にスイープしない**(N-019 が既に「current 値の列挙ドリフトは手動 R1 が要る」と警告済)。

→ **根因(単一)**: フレームワークは schema と撤去語を機械検査し、core↔detail の step 一致を手動検査するが、**宣言↔消費の配線(AP-003)と omission を体系的に検査する機構が機械・手動どちらにも無い**。AP-003 は anti-patterns で「3rd recurrence」と明記された最多再発でありながら、検知を人間/Codex のアドホックに依存していた。バッチB/C は大半が AP-003(宣言のみ・消費なし: strength_start / execution_mode / project TODO / prune)+ omission(S2 active-only)で、まさにこの穴に落ちた。
