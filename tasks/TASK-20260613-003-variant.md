## Search 成果物

### 要求定義(S1)

**何を作るか**

1. **HH-011(変種創設)**: 本指示を裁可として記録。Claude=オーケストレータ / Codex=実行エージェントの2ロールモデルと、`variant/claude-codex` ブランチでの別バージョン管理を創設
2. **agent-roles.md**(AI層・英語): ロール定義、実行エージェントの権限境界、Work Order / Result の契約形式、検証規則(実行エージェントの結果は再検証まで信頼しない)、失敗帰属、縮退モード
3. **配線**: loop.yaml Execute フェーズへの参照(task_list_schema の前例方式)、CLAUDE.md=オーケストレータ入口 / AGENTS.md=実行エージェント入口 という既存2入口の役割分担、git-conventions のブランチモデル、README 注記

**なぜ作るか**

実装作業を Codex に委任する運用には、編集権限の境界(フレームワーク資材の保護)・委任の契約形式・検証責任の所在が事前定義されていないと、知識螺旋のカウンタ整合と証跡主義が崩れる。別ブランチ管理により main(単一エージェント版)の安定を保ったまま変種を進化させる。

**成功条件** — 下の task-list の全行が done。特に: 5フェーズ・ゲート・人間窓口は不変のまま「誰が何をするか」だけが定義されること。validate エラー0(既知警告1のみ)。main に変更が漏れないこと。

**スコープ外**

- Codex の実際の起動・接続設定(運用開始時の別タスク)
- loop.yaml のフェーズ・工程定義の変更(ロールは工程の中の分担であり工程自体を変えない)
- main へのマージ(変種は独立バージョン。マージには受け側での HH を要する — git-conventions に明記)
