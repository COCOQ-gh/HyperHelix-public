## Search 成果物

### 要求定義(S1)

**何を作るか**: ユーザーの2手作業を自動化する。
- **`node tools/hyperhelix.mjs sync`**: B→A を完全自動(fetch → ff 取り込み → validate → push)。**安全境界**: ff 不可(分岐)・validate error・push 拒否では停止し手動へ。force-push しない・counter/notes 衝突は自動解決しない。
- **`node tools/hyperhelix.mjs install-commands --to <hostdir> [--nest <rel>]`**: `.claude/commands/*.md` をホスト作業ディレクトリ直下へ反映。verbatim コピー(ホストが HH チェックアウト時)/ `--nest` でネスト構成の薄いリダイレクタを生成。
- **HH-034(運用規約変更)**: git-conventions の「push は人間指示時のみ」を、**sync ツール経由の push は自動可**(ツール実行=standing 指示、validate+ff 安全で代替)に緩和。ユーザー直接指示につき Approved。

**なぜ作るか**: ユーザー指示(2026-06-20「/sync 実施とコマンドのホスト直下反映が手作業。改善したい」+ AskUserQuestion 回答)。

**成功条件**(観測可能):
1. `sync` が dry-run で B→A 計画を表示、実行で ff+validate+push を自動実施、分岐/error で安全停止。
2. `install-commands` が `.claude/commands/*.md` を `<hostdir>/.claude/commands/` へ反映(verbatim / nest redirect)。
3. HH-034 が amendments(Approved)+ git-conventions + sync.md に反映。
4. help() に両コマンド追記。
5. `node tools/hyperhelix.mjs validate` パス。

**スコープ外**: スケジューラ等での無人 cron 化(ツール提供まで)。多ホスト一括反映(--to を都度指定)。
