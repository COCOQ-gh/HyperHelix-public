| AP-001 | phase-gate,task-brief,real-task | User gives implementation/continue instruction after planning context | Start Execute from chat context without creating/updating task brief | Run phase gate first; create task brief before real-task edits; if already missed, create retrospective brief and log failure | Deliverable exists but Search/Plan/Execute evidence is missing or backfilled | Confusing "user wants action" with "framework evidence can be skipped" | MetaHelix TASK-20260603-004 (inherited HH-000) | high |
| AP-002 | distill-pipeline,counters | Task ends with artifacts shipped and chat summary written | Skip D7 counter updates because "the task is done" | D7 is part of done: update counters (task_index, note), validate before the summary | knowledge.yaml drifts; counters/notes go stale | Treating distill as optional epilogue instead of a required phase | HyperHelix founding (HH-000) | high |
| AP-003 | gates,validation,distill-pipeline,counters | Any parameter, counter, or trigger is declared in a spec/config (gates.yaml, loop.yaml, knowledge.yaml) | Ship the declaration without its consumer: tool wiring, update procedure, or firing check | Declare and wire in the same change: who reads it, when it fires, how it resets; add a validate check or do not declare it. Routine catches (TASK-20260620-014/022/026): framework-review R1 declare↔consume + omission sweep (incl. step-input ↔ upstream-producer, HH-037), and validate's GATE_DEAD_CONFIG (gate params) + PHASE_CONSISTENCY (phase_gate ↔ artifacts) + STEP_CONSISTENCY (required_steps ↔ defined steps). NB: a step that consumes an input no upstream step produces is semantic — caught by the R1 lens / adversarial audit, not a mechanical check | Declaration parsed/stored but never consumed; spec and operation silently diverge (e.g. demotion one-tier rule, layer_active_cap, tuning counters without a review procedure, review triggers without tracking) | Spec written as documentation instead of as a contract with its consumer | HyperHelix TASK-20260611-001 / TASK-20260612-004 (3rd recurrence) | high |
| AP-004 | task-brief,evidence,checklists | A checklist item requires recording a count or value | Satisfy it with prose ("継続", "recorded", "done") that omits the value | Put a literal blank (= ____) in the template line; the reviewer rejects prose-only entries | Required number missing while the box is checked (R6 cycle count missing 3x: TASK-20260612-007/008, TASK-20260613-001) | Checklist wording satisfiable by vague prose; evidence rule did not specify the value form | HyperHelix TASK-20260613-002 | high |
| AP-005 | ui-transition,validation,e2e | A UI command is supposed to move into another engine mode or screen | Treat handler entry/return or a direct function call as proof that the destination screen works | Pair the route contract with a boundary-after check that observes the destination screen/event and scans logs for runtime errors | The command "passes" in a smoke test but crashes after `BEGIN`/mode transition during destination initial rendering | Validation stopped at the caller boundary instead of the first stable destination state | Project001 TASK-20260614-021 | high |
| AP-006 | scope,dependency,blocker,erb-port | A function port is scoped out because "system X is not yet ported" | Mark it blocked at system granularity ("D-04移植後", "主導権システム移植後") without checking whether the function only reads a value vs. needs the write-side system | Decompose dependency: if the function only reads a CSV label, add the label and port now; only block when the function structurally depends on the unported system's logic. Also check if a prior task solved the same dependency type (e.g. color constant→hex). See N-018 | Tasks pile up as "blocked" when they need only trivial CSV additions; throughput stalls on false dependencies | Conflating "data population dependency" (write-side) with "function definition dependency" (read-side); not consulting prior-task patterns | Project001 TASK-20260617-127 | high |
| AP-007 | tool-call,execution,fatal,serialization | Emitting ANY tool/function call | Prefix a stray token (e.g. literal `count`) before the call, or emit bare `<invoke>`/`<parameter>` tags WITHOUT the canonical function-call wrapper | ALWAYS use the exact canonical tool-call format; emit nothing before it. If a call returns "malformed", re-emit in canonical form immediately and verify it executed before continuing | **CRITICAL**: call is unparsed → does not execute → turn ends with no result, work halts SILENTLY mid-task, prior edits left uncommitted / state inconsistent, user must re-prompt. Recurs even after diagnosis | Incorrect tool-call serialization at generation time | Project001 session 2026-06-20 (escalated as fatal after recurrence; see amendments HH-029) | high |
| AP-008 | shell,injection,heredoc,commit,security | Passing variable / file-derived content (commit messages, briefs, notes, amendments) into a shell command | Interpolate it directly (`-m "…$VAR…"`) or via an EXPANDING heredoc `<<EOF` — shell metacharacters `$()`/backtick/`$VAR` in the content get EXECUTED | Use a QUOTED heredoc `<<'EOF'` (body is literal, no expansion); for UNTRUSTED content (project reflux / external origin) pass via `-F <file>` / stdin, never inline. Expand only where actually needed | Backticks / `$(…)` inside a commit message run as commands → commit corrupted or arbitrary command execution (injection). Silent when the content happens to be benign | Shell-construction discipline was unwritten (honor-based); codified by HH-051 in git-conventions.md commit gate | HH-051 / TASK-20260628-066 (near-miss, user-flagged 2026-06-28) | high |
